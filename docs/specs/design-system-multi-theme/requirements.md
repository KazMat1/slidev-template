# 要件: マルチテーマ対応デザインシステム

## 概要
Slidev プレゼンテーションプロジェクトにおいて、PowerPoint のスライドマスタに相当する「マルチテーマ対応デザインシステム」を構築する。現在 ReLic 社向けに1テーマでハードコードされているカラー、タイポグラフィ、レイアウト装飾、ロゴ、フッターなどのデザイン要素を、テーマ切替可能な構造に再設計する。プロジェクト内ディレクトリベースでテーマを管理し、将来的に Slidev テーマパッケージへの昇格が可能なアーキテクチャとする。

## ユーザーストーリー

### US-1: テーマ切替によるデザイン一括変更 (Priority: P1)
スライド作成者として、プレゼンのターゲット（クライアント/用途）に応じてテーマを切り替えるだけで、全レイアウト（cover-1, cover-2, content, section-divider, end）のカラー・タイポグラフィ・装飾・ロゴ・フッターが一括で変わるようにしたい。個別レイアウトの修正なしにブランドの統一感を保つため。

**受入シナリオ**:
1. **Given** プロジェクトに `themes/relic/` と `themes/corporate-b/` が存在する状態で, **When** slides.md のフロントマターまたは設定ファイルでテーマ名を `corporate-b` に変更する, **Then** 全5種のレイアウトが corporate-b のデザイントークン（カラー、フォント、ロゴ、装飾形状）で描画される
2. **Given** テーマを切り替えた状態で, **When** `pnpm dev` で開発サーバーを起動する, **Then** レイアウト Vue ファイルの編集なしにテーマが反映される

**独立テスト**: テーマ名を切り替えて `pnpm dev` を起動し、各レイアウトのスクリーンショットを比較する

### US-2: ReLic テーマの完全移行 (Priority: P1)
プレゼンターとして、現在ハードコードされている ReLic デザイン（Navy/Brown/Pink カラー、遊ゴシック、斜めストライプ装飾、コーナーブラケット、三角形装飾、ReLic ロゴ）が、テーマディレクトリ `themes/relic/` に分離された状態でも、見た目が現行と完全に同一であってほしい。移行による視覚的リグレッションがないことを保証するため。

**受入シナリオ**:
1. **Given** リファクタリング前の全レイアウトのスクリーンショットがある状態で, **When** テーマシステム移行後に `relic` テーマを選択して同じスライドを表示する, **Then** 各レイアウトのピクセル差分が許容範囲内（装飾位置・色・フォントが一致）である
2. **Given** `themes/relic/` テーマが適用された状態で, **When** DataTable コンポーネントを使用する, **Then** ヘッダーが Navy 背景白文字、ボディが白/Gray 交互、行ヘッダーが Brown 背景白文字で描画される

**独立テスト**: 移行前後のスクリーンショットを目視比較し、全5レイアウト + DataTable の一致を確認する

### US-3: テーマのデザイントークン定義 (Priority: P1)
スライド作成者として、各テーマが定義すべきデザイントークン（カラーパレット、フォント、サイズ、装飾パラメータ、ロゴ、コピーライト文言）の仕様が明確に定められていてほしい。新テーマ作成時にどの値を定義すれば全レイアウトが正しく動作するか分かるようにするため。

**受入シナリオ**:
1. **Given** テーマのトークンインターフェース（型定義またはスキーマ）が存在する状態で, **When** 新テーマを作成し必須トークンを一部欠落させる, **Then** ビルド時またはランタイムでエラーまたは警告が表示される
2. **Given** ReLic テーマの定義ファイルが存在する状態で, **When** 定義ファイルを参照する, **Then** カラー6色、フォント2系統、サイズ4段階、copyright文言、ロゴ情報が明示的に記載されている

**独立テスト**: テーマ定義ファイルのスキーマバリデーションを実行し、必須項目の網羅性を検証する

### US-4: テーマごとのレイアウト完全所有 (Priority: P2)
スライド作成者として、テーマごとにレイアウトの種類・数・構造を自由に定義できるようにしたい。テンプレートAは cover-1/cover-2/content/section-divider/end の5種、テンプレートBは cover/content/two-cols/end の4種、のようにテーマ間でレイアウト構成が完全に異なっても対応可能にするため。

**受入シナリオ**:
1. **Given** `themes/relic/layouts/` に5種のレイアウトが定義されている状態で, **When** `themes/corporate-b/layouts/` に異なる4種のレイアウトを定義する, **Then** corporate-b テーマ選択時にそのテーマ固有のレイアウト一式が利用可能になる
2. **Given** テーマのレイアウトに装飾（ストライプ、三角形等）がVueコンポーネントとして組み込まれている状態で, **When** テーマを切り替える, **Then** 装飾も含めてレイアウト全体がテーマに応じたものに変わる

**独立テスト**: 2つの異なるテーマで `layout:` を指定してビルドし、各テーマ固有のレイアウトが正しく描画されることを確認する

### US-5: テーマ固有のロゴとフッター (Priority: P2)
プレゼンターとして、テーマ切替時にロゴ画像（またはテキストロゴ）とフッターの copyright 文言が自動的にテーマに応じた内容に切り替わってほしい。手動でロゴやフッターを編集する手間を省くため。

**受入シナリオ**:
1. **Given** `themes/relic/` に ReLic ロゴと copyright が定義されている状態で, **When** テーマを `corporate-b` に切り替える, **Then** ロゴが corporate-b のロゴに、copyright が corporate-b の文言に自動的に変わる
2. **Given** テーマにロゴ画像パスが指定されている状態で, **When** cover-1 レイアウトを表示する, **Then** 指定画像がロゴとして表示される（テキストフォールバックではなく）

**独立テスト**: テーマを切り替えてロゴ・フッターの内容が変わることを確認する

### US-6: 新テーマの追加容易性 (Priority: P2)
スライド作成者として、既存テーマをコピーして新テーマを作成する際、変更すべきファイルと手順が明確で、最小限の作業で新テーマを追加できるようにしたい。テーマの拡張性を確保するため。

**受入シナリオ**:
1. **Given** `themes/relic/` ディレクトリが存在する状態で, **When** ディレクトリをコピーして `themes/new-client/` を作成しトークン値を変更する, **Then** `new-client` テーマが正常に動作する
2. **Given** テーマ追加手順のドキュメントが存在する状態で, **When** 手順に従って新テーマを追加する, **Then** レイアウトファイルの変更なしに新テーマが利用可能になる

**独立テスト**: relic テーマをコピーしてトークン値のみ変更した新テーマを追加し、全レイアウトが動作することを確認する

### US-7: Slidev テーマパッケージへの将来的昇格 (Priority: P3)
スライド作成者として、ディレクトリベースのテーマが将来的に Slidev 公式テーマパッケージ（npm パッケージ）として切り出せる構造になっていてほしい。他プロジェクトへの再利用やエコシステムへの貢献を可能にするため。

**受入シナリオ**:
1. **Given** `themes/relic/` のディレクトリ構造が Slidev テーマパッケージ規約（layouts/, components/, styles/ など）に準拠している状態で, **When** package.json を追加して npm パッケージ化する, **Then** 他の Slidev プロジェクトから `theme: relic` で利用可能になる

**独立テスト**: テーマディレクトリの構造が Slidev テーマ規約に沿っていることをディレクトリ構成の比較で確認する

## エッジケース

- **存在しないテーマ名の指定**: 指定されたテーマディレクトリが存在しない場合、明確なエラーメッセージを表示しフォールバック動作（デフォルトテーマまたはエラー表示）を行う
- **テーマトークンの部分欠落**: テーマ定義で一部のトークン（例: アクセントカラー）が未定義の場合、CSS カスタムプロパティのフォールバック値でデフォルトが適用される
- **ロゴ画像の欠落**: テーマにロゴ画像パスが指定されているが画像ファイルが存在しない場合、テキストロゴにフォールバックする
- **フォント未インストール環境**: 指定フォント（遊ゴシック等）がインストールされていない環境では、font-family チェーンの次のフォールバックフォントで描画される
- **テーマ切替時のホットリロード**: 開発サーバー実行中にテーマ名を変更した場合、ホットリロードで即座にデザインが反映される（Vite の HMR 対応範囲内）
- **DataTable のテーマ連動**: DataTable コンポーネントのヘッダー色・行ヘッダー色がテーマのカラートークンに連動して変わること

## 機能要件

- **FR-001**: システムはプロジェクト内 `themes/{theme-name}/` ディレクトリからテーマ定義を読み込み、全レイアウトに適用する仕組みを提供しなければならない
- **FR-002**: テーマ定義には最低限以下のデザイントークンを含まなければならない: カラーパレット（primary, secondary, accent, background, text 等）、フォントファミリー（和文/欧文）、フォントサイズ（H1/H2/Body/Small）、copyright 文言、ロゴ情報
- **FR-003**: SlideMaster コンポーネントは現在のハードコードされた設定値（copyright, logo 等）をテーマ定義から動的に取得しなければならない
- **FR-004**: 各テーマは `themes/{name}/layouts/` 配下にレイアウト一式を完全に所有し、テーマ間でレイアウトの種類・数・構造が異なることを許容しなければならない
- **FR-005**: DataTable コンポーネントはテーマのカラートークン（ヘッダー色、行ヘッダー色、交互背景色）を参照しなければならない
- **FR-006**: テーマ切替は slides.md のフロントマター `addons` の1箇所の変更のみで完了しなければならない（例: `addons: ['./themes/relic']` → `addons: ['./themes/corporate-b']`）
- **FR-007**: 各テーマのレイアウトは装飾コンポーネント（ストライプ、三角形等）を Vue コンポーネントとして内包し、SlideMaster の decoration スロットを通じて表示しなければならない
- **FR-008**: テーマディレクトリの構造は Slidev 公式テーマパッケージの規約（layouts/, components/, styles/ サブディレクトリ）と互換性のある構成としなければならない
- **FR-009**: CSS カスタムプロパティ（CSS Variables）をテーマトークンの受け渡し手段として使用し、styles/index.css の `:root` 定義をテーマごとに差し替え可能にしなければならない
- **FR-010**: テーマにロゴ画像パスが指定されている場合は画像を表示し、未指定の場合はテキストロゴにフォールバックしなければならない

## 非機能要件

- **NFR-001**: テーマ切替はコードベースの変更1箇所（設定値の変更）で完結し、レイアウト Vue ファイルの編集を要しないこと
- **NFR-002**: 新テーマの追加は既存テーマディレクトリのコピーとトークン値・レイアウトの変更で可能であること（目安: カラー/ロゴ差し替えのみなら30分、レイアウト構造変更含む場合は別途）
- **NFR-003**: テーマ切替が開発サーバーのビルド時間に有意な影響を与えないこと（現行比 +10% 以内）
- **NFR-004**: テーマ構造は Slidev v51 の API と互換性を維持すること
- **NFR-005**: テーマのデザイントークンは TypeScript の型定義で文書化されること

## 成功基準

- **SC-001**: ReLic テーマが `themes/relic/` に分離された状態で、全5レイアウトの表示が移行前と視覚的に一致すること
- **SC-002**: テーマ名の切替（1箇所の変更）のみで全レイアウトのデザインが変更されること
- **SC-003**: 第2テーマ（ダミーまたはモックでよい）を追加し、正常にレイアウトが描画されること
- **SC-004**: テーマディレクトリ構造が Slidev テーマパッケージ規約の layouts/, components/, styles/ 構成に準拠していること
- **SC-005**: DataTable を含む全コンポーネントがテーマのカラートークンに連動して色が変わること

## 前提条件

- Slidev v51 + Vue 3 + TypeScript + UnoCSS の技術スタックを使用する
- monorepo 構成（apps/preview 配下）で開発する
- 既存の SlideMaster.vue、5レイアウト（cover-1, cover-2, content, section-divider, end）、DataTable コンポーネントが存在する
- 現行の ReLic デザイン（カラー6色、遊ゴシック/Arial フォント、斜めストライプ/三角形装飾）が CSS カスタムプロパティで部分的にトークン化済みである
- styles/index.css の `:root` に ReLic テーマのデザイントークンが定義済みである

## スコープ外

- Slidev テーマパッケージとしての npm 公開（将来対応。ディレクトリ構造の互換性のみ本スコープ）
- テーマの GUI エディタやビジュアルカスタマイズツール
- ダークモード/ライトモードの切替機能（テーマ内の footerTheme dark/light とは別の概念）
- テーマのランタイム切替（プレゼン中のリアルタイムテーマ変更）
- ReLic 以外の本番テーマのデザイン策定・実装（構造検証用のダミーテーマは含む）
- PDF/PNG エクスポート時のテーマ対応検証（基本動作は期待するが詳細検証はスコープ外）
- フォントファイルのバンドル（システムフォントへのフォールバックで対応）

## 解決済み事項

- **テーマの選択方法**: Slidev addon 機能を使用。slides.md のフロントマターで `addons: ['./themes/relic']` と指定する方式を採用。Slidev 標準の仕組みのため独自設定ファイル不要。
- **テーマごとの装飾注入方式**: 各テーマが Vue コンポーネントとして装飾を提供する方式を採用（`themes/relic/components/decorations/CoverStripes.vue` 等）。テーマごとに完全に異なるビジュアル（ストライプ/円/写真等）が可能。
- **レイアウトの管理方式**: テーマごとにレイアウトを完全に持つ方式を採用。各テーマが `themes/{name}/layouts/` 配下にレイアウト一式を所有する。テーマ間でレイアウトの種類・数・構造が異なってもよい（テンプレートAが5種、テンプレートBが4種で全く違う構成でもOK）。SlideMaster は共通基盤コンポーネントとして `components/` に残り、各テーマのレイアウトが import して利用する形で重複を吸収する。
