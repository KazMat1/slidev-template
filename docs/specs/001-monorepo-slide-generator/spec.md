# Feature Specification: Monorepo スライド自動生成アプリ

**Feature Branch**: `001-monorepo-slide-generator`
**Created**: 2026-03-25
**Status**: Draft
**Input**: User description: "pnpm workspace, turbopack, slidevでスライドを生成するアプリを作って"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 箇条書きからスライド生成 (Priority: P1)

ユーザーは箇条書きやトピック概要をテキストで入力し、プロフェッショナルなプレゼンテーションスライドを自動生成できる。生成されたスライドはブラウザでプレビュー可能で、PDF としてエクスポートできる。

**Why this priority**: アプリの核となる機能。これが動作すれば MVP として成立し、ユーザーに即座に価値を提供できる。

**Independent Test**: テキスト入力画面から箇条書きを入力し、「生成」ボタンを押すと Slidev 形式のスライドが生成され、ブラウザプレビューで確認できることをテスト可能。

**Acceptance Scenarios**:

1. **Given** テキスト入力画面が表示されている, **When** ユーザーが箇条書きテキスト（5〜30行程度）を入力して生成を実行する, **Then** Slidev マークダウン形式のスライドが生成され、プレビュー画面に表示される
2. **Given** スライドが生成されている, **When** ユーザーがプレビュー画面を開く, **Then** Slidev の開発サーバーでスライドがレンダリングされ、ブラウザ上でスライドを閲覧できる
3. **Given** スライドが生成されている, **When** ユーザーが PDF エクスポートを実行する, **Then** スライドが PDF ファイルとして出力される

---

### User Story 2 - テンプレート選択によるデザイン適用 (Priority: P2)

ユーザーは事前定義されたテンプレート（提案書、技術発表、レポート等）を選択し、生成されるスライドのデザインやレイアウト構成をカスタマイズできる。

**Why this priority**: テンプレートにより生成品質が大幅に向上する。ユーザーの用途に合ったスライドを出力するために重要。

**Independent Test**: テンプレート選択 UI からテンプレートを選び、同じ入力テキストで異なるデザインのスライドが生成されることを確認できる。

**Acceptance Scenarios**:

1. **Given** テンプレート一覧が表示されている, **When** ユーザーが「提案書」テンプレートを選択して生成を実行する, **Then** 提案書向けのレイアウト構成（cover→agenda→section→conclusion 等）でスライドが生成される
2. **Given** テンプレート一覧が表示されている, **When** ユーザーが「技術発表」テンプレートを選択して生成を実行する, **Then** 技術発表向けのレイアウト（コードブロック、アーキテクチャ図配置等）でスライドが生成される

---

### User Story 3 - 生成済みスライドの編集・再生成 (Priority: P3)

ユーザーは生成されたスライドのマークダウンを直接編集できる。また、特定のスライドだけを再生成したり、指示を追加して再生成できる。

**Why this priority**: 生成結果の微調整は実用上不可欠だが、まずは生成機能とテンプレートが揃った後に対応すべき。

**Independent Test**: 生成済みスライドの編集画面でマークダウンを変更し、プレビューにリアルタイム反映されることを確認できる。

**Acceptance Scenarios**:

1. **Given** スライドが生成されている, **When** ユーザーがマークダウンエディタでスライド内容を編集する, **Then** 変更がリアルタイムでプレビューに反映される
2. **Given** スライドが生成されている, **When** ユーザーが追加指示（「もっと簡潔に」「図を追加して」等）を入力して再生成する, **Then** 指示を反映した新しいスライドが生成される

---

### User Story 4 - プロジェクト管理 (Priority: P3)

ユーザーは複数のプレゼンテーションプロジェクトを作成・管理できる。各プロジェクトには入力テキスト、生成設定、生成済みスライドが保存される。

**Why this priority**: 継続的な利用には必要だが、単発利用でも P1/P2 の機能で価値を提供可能。

**Independent Test**: プロジェクト一覧画面で新規作成・既存プロジェクトの再開ができることを確認できる。

**Acceptance Scenarios**:

1. **Given** アプリのホーム画面が表示されている, **When** ユーザーが「新規プロジェクト」を作成する, **Then** プロジェクトが保存され、一覧に表示される
2. **Given** プロジェクト一覧に既存プロジェクトがある, **When** ユーザーがプロジェクトを選択する, **Then** 以前の入力テキストと生成済みスライドが復元される

---

### Edge Cases

- 入力テキストが空または極端に短い（1行のみ）場合、最低限のスライド（タイトルのみ等）が生成される
- 入力テキストが非常に長い（100行以上）場合、適切にセクション分割されて複数スライドに展開される
- 生成中にネットワークエラーや AI API のタイムアウトが発生した場合、ユーザーにエラーメッセージが表示され、再試行できる
- 日本語と英語が混在する入力テキストでも正しくスライドが生成される
- 同時に複数の生成リクエストが発行された場合、それぞれ独立して処理される

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは pnpm workspace によるモノレポ構成で、フロントエンド（入力 UI）とスライド生成エンジンを分離して管理できなければならない
- **FR-002**: システムはユーザーが入力したテキスト（箇条書き、自由記述）を受け取り、Slidev 互換のマークダウンスライドを生成できなければならない
- **FR-003**: 生成されたスライドは Slidev 開発サーバーでブラウザプレビューできなければならない
- **FR-004**: システムは生成されたスライドを PDF 形式でエクスポートできなければならない
- **FR-005**: システムは複数のスライドテンプレート（レイアウト構成、デザインテーマ）を提供し、ユーザーが選択できなければならない
- **FR-006**: 生成されるスライドは Slidev の標準レイアウト（cover, default, two-cols, section, fact, quote, end 等）を適切に活用しなければならない
- **FR-007**: 生成されるスライドにはクリックアニメーション（v-click, v-clicks）が適切に適用されなければならない
- **FR-008**: システムはカスタム Vue コンポーネント（DataTable, CompareCards, StepFlow, KpiHighlight 等）をスライド内で利用できなければならない
- **FR-009**: システムは Turborepo をモノレポのタスクランナーとして使用し、ビルド・テストの並列実行とキャッシュにより開発効率を最適化しなければならない
- **FR-010**: ユーザーはマークダウンエディタでスライド内容を直接編集でき、変更がリアルタイムでプレビューに反映されなければならない
- **FR-011**: システムは生成履歴をプロジェクト単位で保存し、後から再開・再編集できなければならない

### Key Entities

- **プロジェクト**: ユーザーが作成するプレゼンテーション単位。入力テキスト、選択テンプレート、生成設定、生成済みスライドを含む
- **テンプレート**: スライドのレイアウト構成・デザインテーマ・使用コンポーネントを定義したプリセット。提案書、技術発表、レポート等の種類がある
- **スライドセット**: 生成された Slidev マークダウンファイル群。メインの slides.md と、必要に応じて pages/ 配下の分割ファイル、components/、styles/ を含む

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは 20 行程度の箇条書きから 10〜20 ページのプレゼンテーションスライドを 2 分以内に生成できる
- **SC-002**: 生成されたスライドは Slidev で正常にレンダリングされ、ビルドエラーが発生しない
- **SC-003**: 3 種類以上のテンプレートが利用可能で、同じ入力テキストから異なるデザインのスライドを生成できる
- **SC-004**: 生成されたスライドの 80% 以上が、手動修正なしでプレゼンテーションに使用できる品質である
- **SC-005**: 入力テキストからスライド生成→PDF エクスポートまでの全工程を 5 分以内に完了できる
- **SC-006**: モノレポ構成の各パッケージが独立してビルド・テスト可能である

## Assumptions

- ユーザーは Node.js（v18 以上）と pnpm がインストールされた開発環境を持っている
- AI によるスライド生成には外部 AI API（Claude API 等）を使用する。API キーはユーザーが用意する
- 初期テンプレートは「提案書」「技術発表」「一般プレゼン」の 3 種類を提供する
- スライドのデザインは UnoCSS（Tailwind 互換）ベースのスタイリングを使用する
- フロントエンド UI は Web ブラウザで動作するアプリケーションとする
- カスタム Vue コンポーネントは参考記事（gmoconnect/proposal-slide-sample）のパターンを参考に実装する
- Turborepo をモノレポのタスクランナーとして使用し、各パッケージのビルド・テストを並列実行・キャッシュする。Slidev 側は Vite を使用する
