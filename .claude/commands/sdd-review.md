# SDD Review

`slides.md` の品質レビューを実行する独立コマンド。
`/sdd` Phase 6b のレビューと同等だが、パイプライン外で任意のスライドに使える。

## 引数

- `$ARGUMENTS` — spec-name（オプション）。指定時は要件・設計との整合性もチェック。

---

## 実行手順

### 1. 入力ファイルの確認

必須:
- `slides.md`

オプション（spec-name 指定時）:
- `docs/specs/{spec-name}/requirements.md`
- `docs/specs/{spec-name}/design.md`

`slides.md` が存在しない場合はエラーを報告して終了。

### 2. SubAgent 委譲

Task ツールで `slide-reviewer` 相当のエージェントを起動する。

```
Task ツール呼び出し:
  subagent_type: "general-purpose"
  description: "スライドレビュー"
  prompt: |
    あなたは slide-reviewer です。生成されたスライドをレビューしてください。
    **STRICTLY READ-ONLY**: ファイルは一切変更しないこと。

    ## 入力
    - slides.md
    - docs/specs/{spec-name}/requirements.md（spec-name 指定時のみ）
    - docs/specs/{spec-name}/design.md（spec-name 指定時のみ）

    ## 参照
    - docs/reference/slidev-knowhow.md — レイアウト一覧・設計原則
    - docs/reference/slide-patterns.md — パターンカタログ

    ## チェック項目

    ### 1. 構文検証
    - Slidev フロントマターの正当性
    - `---` 区切りの正しい使用
    - レイアウト名の有効性
    - コードブロックの言語指定
    - コンポーネントタグの閉じ忘れ

    ### 2. コンテンツ密度
    - 1スライドあたりの箇条書き数（7項目以下が目標）
    - テキスト量の適切さ（3秒ルール）
    - 情報の重複チェック

    ### 3. レイアウト多様性
    - レイアウトの種類数と分布
    - 同じレイアウトが3枚以上連続していないか
    - コンテンツに適したレイアウトが選択されているか

    ### 4. ストーリーフロー
    - 論理的な流れ（起承転結）
    - タイトル→本題→まとめの構成

    ### 5. 要件・設計との整合性（spec-name 指定時のみ）
    - requirements.md の要件がスライドに反映されているか
    - design.md のスライド構成表との整合性
    - 非機能要件（スライド枚数、聴衆レベル）の反映

    ## 出力フォーマット
    ```markdown
    # スライドレビューレポート

    ## 総合スコア: X/5

    ## サマリー
    [全体的な評価を2-3文で]

    ## 重大（Critical）
    - [修正必須の問題]

    ## 改善推奨（Warning）
    - [改善した方がよい問題]

    ## 提案（Info）
    - [あるとより良くなる改善案]

    ## スライド別メモ
    | # | レイアウト | 密度 | メモ |
    |---|----------|------|------|
    ```

    ## 制約
    - 日本語で記述
    - ファイルの変更は一切行わない（読取専用）
    - 構造化されたレビューレポートを出力
```

### 3. SubAgent 完了後

1. レビューレポートをユーザーに提示
2. 修正が必要な場合は改善ポイントを要約

---

## 注意事項

- **読取専用**: このコマンドはファイルを一切変更しない
- `/sdd` パイプライン外で作成したスライドにも使用可能
- spec-name を省略した場合は構文・密度・レイアウトのチェックのみ実行
- spec-name を指定した場合は要件・設計との整合性チェックも追加
